# 医院超声诊断工作台修复与布局改造设计

日期：2026-07-12

## 目标

在保留现有配色、字体、圆角、轻边框和整体视觉气质的前提下，提高医院宽屏工作站的页面利用率，减少病例阅片与医生确认之间的点击和滚动成本，并修复当前构建、批量任务及临床判断流程中的明确缺陷。

## 范围

本轮包含：

- 单例推理、病例详情、病例历史、批量任务及设置页的前端布局和交互。
- 医生最终判断的数据模型、保存规则和审计信息。
- 批量任务空工作队列、取消操作和失败状态处理。
- 当前 TypeScript 构建与 ESLint 错误。

本轮不包含：

- 科室级、医生级病例访问隔离。
- 医院 HIS、PACS 或统一身份认证对接。
- 模型结构、训练数据或推理阈值重新标定。
- 全新的视觉品牌或配色方案。

## 已确认决策

### 权限范围

现阶段所有已登录医生都可以查看和修改病例。后端将权限判断保留在集中入口，方便医院对接时按科室、医生或授权范围收紧，但本轮不改变现有共享行为。

### 视觉系统

继续使用当前米白背景、白色内容面、现有语义色、系统中文字体、6–8 px 圆角和轻边框。不进行换肤，不引入新的装饰语言。改造重点是空间结构、信息层级和操作路径。

### 医生判断

- AI 输出明确标记为“AI 辅助建议”，不作为医生判断默认值。
- 医生判断初始为空，必须主动选择后才能保存。
- 选项为：正常、息肉、疑似子宫内膜癌、无法判断 / 需进一步检查。
- 已保存判断再次编辑时显示原判断、医生和时间。
- 修改判断时更新判断时间，并在审计日志中记录修改前后的内容。

## 页面设计

### 全局布局

核心业务页面的最大内容宽度调整为 `min(1600px, 100%)`，保留适度的 16–24 px 页面边距。固定格式工具区通过明确的网格轨道控制尺寸，不依赖大量空白维持视觉平衡。

### 单例推理

初始状态保留输入区和空结果区双栏，避免在无数据时展示复杂工作台。

推理完成后切换为三栏诊断工作台：

1. 左栏约 240 px：病例基本信息、检查所见、图像缩略图。
2. 中栏自适应：原图与 Grad-CAM 对照、逐图选择、当前图预测。
3. 右栏约 360 px：AI 辅助建议、概率分布、医生最终判断和保存操作。

右栏在桌面端粘性定位。移动端按病例信息、影像、AI 建议、医生判断的顺序纵向排列。

保存操作提供“保存”和“保存并下一例”。后者仅在存在明确下一例上下文时显示，不凭空猜测目标病例。

### 病例详情

病例详情复用相同三栏工作台组件，避免单例结果页与历史详情页出现两套不同交互。原图与热图使用稳定比例，缩略图选择不改变整体布局尺寸。

### 历史记录

- 使用接近全宽的数据表，提高宽屏利用率。
- 筛选器保持一行紧凑布局，窄屏自动换行。
- 取消 `tr` 整行点击。
- 病例编号使用真实链接作为唯一详情入口，移除重复的“操作”列。
- 表格链接具备键盘焦点和可辨识的悬停状态。

### 批量任务

批量任务入口采用“新建任务、运行中、历史记录”三个页面内标签：

- 新建任务：上传区优先，格式说明折叠为次要内容。
- 运行中：显示当前患者、进度、预计剩余时间和取消操作。
- 历史记录：任务 ID 使用真实链接，不使用整行点击。

批量详情保留左侧患者列表和右侧详情，但将宽度提升到全局工作区标准。失败患者在列表中显示可读原因。

### 设置页

删除当前仅保存在浏览器本地、且未影响任何预测显示的“置信度阈值”滑块。本轮不新增未经标定的低置信度标签，只展示模型返回的原始概率；后续阈值必须经过验证并由后端统一下发。

## 组件边界

- `WorkspaceContainer`：统一业务页面宽度和响应式边距。
- `ClinicalWorkbench`：组织左侧病例、中央影像和右侧判断三个区域。
- `ImageReviewPanel`：处理原图、Grad-CAM、缩略图与逐图结果。
- `AiSuggestionPanel`：只展示模型建议和概率，不持有医生输入状态。
- `JudgmentForm`：只管理医生主动输入；新判断未选择时不可提交，编辑已有判断时载入已保存值。
- 表格导航统一使用 React Router `Link`，不在表格行挂载导航事件。

组件之间通过现有类型对象传值，不复制 API 请求逻辑。React Query 继续负责病例、任务和保存后的缓存刷新。

## 后端与数据流

### 判断保存

前端提交扩展后的医生判断枚举。后端验证合法值，创建或更新判断记录。更新时同步写入新的 `judged_at`，并记录旧值和新值到审计详情。

数据库已有字符串字段，无需破坏性迁移。API 响应保持现有结构。

### 批量任务

批量提交保存图像后，如果没有任何可执行的患者工作项，则不启动后台线程。任务应立即进入失败状态，记录明确错误，并向前端返回可操作的信息。

运行任务可以通过现有取消 API 取消。前端取消前进行明确确认，取消成功后刷新任务状态。后台在每张图像前继续检查取消状态。

单张图像等待超时不得当作正常完成。超时应记录该图失败原因，并避免迟到回调造成状态误判。

## 错误处理

- 输入校验错误直接靠近对应控件展示。
- 系统错误提供原因和下一步，不只显示“请求失败”。
- 批量失败区分压缩包格式、清单错误、无有效图像、推理超时和服务重启。
- 医生离开存在未保存判断的页面前进行提醒。
- 所有图像缺失或热图不可用时保持稳定布局，并显示明确占位状态。

## 测试与验收

### 自动验证

- 前端 `npm run build` 通过。
- 前端 `npm run lint` 通过。
- 后端模块编译通过。
- 判断表单覆盖未选择不可提交、新增“无法判断”以及已保存判断编辑。
- 批量流程覆盖全部图像无效、取消任务和单图超时。
- 历史表格覆盖链接导航和键盘可访问性。

### 视觉验证

在 1920×1080、1440×900 和移动端视口检查：

- 核心工作台没有无意义的大面积留白。
- 三栏不重叠，按钮和中文文本不溢出。
- 影像区域保持稳定尺寸。
- 医生判断在常见桌面视口首屏可见。
- 移动端按临床阅读顺序排列。

### 数据安全

视觉验证优先使用现有合法登录态。若没有可用登录态，使用隔离测试数据，不修改现有医院病例、账号或会话。

## 实施顺序

1. 修复现有构建与规范错误，建立可验证基线。
2. 修复医生判断枚举、审计时间和批量空任务问题。
3. 建立共享工作台布局组件。
4. 改造单例推理与病例详情。
5. 改造历史表格和批量任务导航、取消路径。
6. 删除无效设置并统一低置信度显示规则。
7. 执行自动测试和多视口视觉验收。
