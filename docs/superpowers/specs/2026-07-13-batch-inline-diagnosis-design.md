# 批量任务就地诊断设计

## 背景与目标

当前批量任务详情页只能查看患者级 AI 结果和逐图摘要。医生必须进入单病例详情页才能填写最终判断，连续处理整批患者时会反复跳转页面，打断阅片节奏。

本次改造将批量任务详情页升级为可连续阅片和诊断的临床工作台。医生在批量推理尚未全部结束时，即可处理已经完成推理的患者；保存判断后既可以停留当前患者，也可以直接进入下一位未诊断患者。

## 设计原则

- 保留现有配色、字体、边框、圆角和临床工作台视觉语言。
- 医生诊断必须基于完整影像、AI 建议和临床信息，不提供脱离影像上下文的列表内快速判断。
- 批量推理进度与医生诊断进度分开表达。
- 复用现有单病例组件和接口，避免出现两套诊断语义。
- 不改变现阶段的共享查看权限，也不增加批量采纳 AI 结果等高风险操作。

## 页面布局

桌面端采用与单病例详情一致的三栏工作台：

```text
患者队列 240px       影像阅片 flexible          AI + 医生判断 360px
┌─────────────┐  ┌──────────────────────┐  ┌─────────────────┐
│ 全部 未诊断  │  │ 原图       Grad-CAM  │  │ AI 辅助建议      │
│ 已诊断 失败  │  │                      │  ├─────────────────┤
│ ● 8502118   │  │ 缩略图与逐图预测       │  │ 医生最终判断      │
│ ✓ 6719922   │  │                      │  │ 保存判断          │
│ ! 6528576   │  │ 患者级概率分布         │  │ 保存并下一位       │
└─────────────┘  └──────────────────────┘  └─────────────────┘
```

- 左栏：患者筛选、诊断进度和患者队列。
- 中栏：正式影像阅片区，复用 `ImageReviewPanel`。
- 右栏：AI 辅助建议和医生最终判断，复用 `AiSuggestionPanel` 与 `JudgmentForm`。
- “打开完整详情”保留为补充入口，但不再是完成诊断的必经步骤。

移动端按患者队列、影像、AI 建议、医生判断的顺序纵向排列。患者队列使用紧凑横向滚动，避免长列表占据整个首屏。

## 患者队列与筛选

患者队列提供四个筛选视图：

- 全部：显示批次中的所有患者。
- 未诊断：推理成功且没有医生最终判断。
- 已诊断：已保存医生最终判断。
- 推理失败：没有可用预测并带有失败原因。

默认进入“未诊断”视图并选中第一位未诊断患者。如果没有未诊断患者，则切换到“全部”并选中第一位推理成功的患者。推理失败患者可被选中查看失败原因，但诊断表单不可用。

每个患者项显示患者编号、AI 分类、置信度和医生诊断状态。已诊断状态来自病例详情中的 `judgment`，不得根据 AI 结果推断。

## 连续诊断流程

批量任务运行期间，已完成推理的患者立即进入可诊断队列，不需要等待整个任务结束。

诊断表单提供两个明确操作：

- 保存判断：保存成功后停留当前患者。
- 保存并下一位：保存成功后选择当前筛选范围内的下一位未诊断患者；如果当前筛选范围没有候选，则在全部未诊断患者中寻找下一位。

当最后一位未诊断患者保存完成时，页面停留当前患者，并提示“本批次已全部诊断”。保存成功后立即刷新当前病例、患者诊断状态和诊断进度，不重新加载整页。

如果诊断表单存在未保存修改，医生切换患者、改变筛选或离开页面时必须触发现有未保存内容保护。取消离开后继续保留当前表单内容。

## 数据流与组件边界

批量状态接口继续返回患者摘要，页面按 `case_id` 懒加载当前病例详情，避免一次下载整批影像数据。

`BatchDetail` 负责：

- 批量推理状态和患者摘要轮询。
- 筛选状态、当前患者和连续诊断导航。
- 分别计算 AI 推理进度与医生诊断进度。

可复用工作台内容负责：

- `ImageReviewPanel`：当前患者原图、Grad-CAM、缩略图和逐图预测。
- `AiSuggestionPanel`：患者级 AI 分类与概率。
- `JudgmentForm`：医生分类、处置建议、备注、保存状态和未保存保护。

为了支持两个保存操作，`JudgmentForm` 增加可选的次级提交动作，但保持单病例页面现有调用方式不变。批量页在保存成功后失效当前病例查询和批量摘要查询，使医生状态立即更新。

后端批量状态响应的每个患者摘要增加 `has_judgment: boolean`。列表只使用该字段筛选和显示诊断状态，具体诊断内容仍由当前病例详情提供。不得为列表状态逐患者发起额外病例请求。

## 状态与异常

- 病例详情加载中：中栏和右栏显示稳定尺寸的加载状态，左栏仍可操作。
- 病例详情加载失败：保留当前患者选择，显示错误和重试操作。
- 判断保存失败：保留医生输入，显示具体错误，两个保存操作恢复可用。
- 推理失败：显示患者级失败原因，不渲染可提交的诊断表单。
- 批量仍在运行：继续轮询新增结果，但不得覆盖医生当前选择和未保存输入。
- 当前患者因轮询更新诊断状态：仅在没有本地未保存内容时同步服务端值。

## 可访问性与点击逻辑

- 患者筛选使用带选中状态的分段控件，并提供可读标签和数量。
- 患者项使用真实按钮，支持键盘聚焦和 Enter/Space 选择。
- 两个保存按钮名称保持稳定，提交中禁用，避免重复保存。
- 当前患者、已诊断、推理失败不能只靠颜色区分，必须同时提供文本或图标状态。
- 移动端按钮文字不得截断或互相覆盖。

## 测试与验收

自动化测试至少覆盖：

- 默认筛选并选中第一位未诊断患者。
- 全部、未诊断、已诊断、推理失败四类筛选。
- 批量运行期间对已完成患者进行诊断。
- “保存判断”停留当前患者。
- “保存并下一位”切换到下一位未诊断患者。
- 最后一位保存后显示全批完成提示。
- 保存失败时保留输入并允许重试。
- 切换患者或筛选时的未保存内容保护。
- 批量轮询不重置当前患者和表单。
- 桌面三栏布局与移动端排列顺序。

视觉验收覆盖 1920x1080、1440x900 和 390x844，检查页面横向溢出、患者队列可用性、诊断表单首屏可见性和按钮文字完整性。

## 非目标

- 不增加批量一键采纳 AI 结果。
- 不增加批量修改多位患者诊断。
- 不调整模型分类或推理流程。
- 不收紧病例或批量任务权限。
- 不重新设计项目配色与基础视觉样式。
