# 项目说明文档更新设计

## 目标

更新项目现有说明文档，使其准确反映当前医院超声辅助诊断系统的临床流程、技术实现、部署方式和运维边界。文档同时服务医院使用者、研发人员和科研展示，不描述尚未落地的功能。

## 文档分层

### 根目录中文 README

`README.md` 是中文主入口，包含：

- 系统定位、适用场景和临床责任边界。
- 单例推理、批量推理、三栏阅片和医生最终判断流程。
- 当前模型结构、推理类别、Grad-CAM 和患者级聚合。
- 批量任务页内连续诊断、筛选、保存并下一位和并发冲突保护。
- 技术栈、项目结构、快速启动、部署入口、测试命令和 API 概览。
- 数据、模型权重和医院接入前需要进一步收紧的安全边界。

### 根目录英文 README

`README_EN.md` 与中文 README 使用相同章节结构和事实口径。英文内容不是逐句机械翻译，但所有功能、路径、默认值、限制和警告必须一致。

### 后端 README

`backend/README.md` 面向后端开发和部署人员，包含：

- Python 环境、依赖安装、模型文件、开发与生产启动。
- FastAPI 路由、SQLite 数据、上传目录和批量队列结构。
- 单例与批量推理状态、取消/超时语义、医生判断版本冲突机制。
- 后端测试、编译检查、健康检查和常见开发问题。

### 前端 README

`frontend/README.md` 完全替换 Vite 模板说明，包含：

- React 应用的实际页面与临床工作流。
- 三栏工作台、批量患者筛选、连续诊断和未保存保护。
- 开发启动、后端代理、构建、测试和 lint 命令。
- 目录结构、查询缓存、路由和组件边界。

### 部署文档

`docs/deployment.md` 修正旧模型名称、旧路径和过时限制，明确当前 EfficientNet-B3 + 医学 BERT 权重位置、前端构建顺序、systemd/Nginx、环境变量、备份和升级验证。

### 运维手册

`docs/runbook.md` 保留面向值班人员的操作结构，增加批量任务、推理队列、模型状态、医生判断冲突、数据库锁和终态异常排查。命令必须可直接执行，危险操作必须要求先备份或确认。

## 内容原则

- 只写代码和测试已经证明存在的能力。
- 保留现有配色和界面描述，不加入营销式语言。
- 明确 AI 只提供辅助建议，医生判断必须主动保存。
- 当前所有已登录医生可共享查看病例和批量任务；说明医院正式接入时需要按院方要求收紧权限，但不宣称当前已经实现科室隔离。
- 不在仓库中保存模型权重、真实患者数据、生产密码或密钥。
- ZIP 批量格式必须说明 `manifest.csv` 位于压缩包根目录，患者目录名与 `patient_no` 对应。
- 医生判断分类与模型分类分开：模型为三分类，医生判断增加“无法判断 / 需进一步检查”。

## 一致性检查

更新后执行：

- 比较中英文 README 的章节、命令、路径、类别和限制。
- 检索旧模型 `ResNet18`、`bert-base_fold1_best.pth`、旧 BERT 路径和错误图像数量。
- 核对 README 中引用的文件、脚本、API 和环境变量确实存在。
- 运行 Markdown 链接和格式的基本检查，以及 `git diff --check`。

## 非目标

- 不修改生产代码、依赖或数据库。
- 不创建新的产品功能或部署脚本。
- 不重写项目历史或移动大文件到 Git LFS。
- 不承诺尚未完成的医院接口、单点登录、PACS/HIS 对接或严格权限模型。
