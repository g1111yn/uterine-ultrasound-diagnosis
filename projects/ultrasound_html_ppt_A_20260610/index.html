这一页先建立项目全貌。它不是单纯的模型 demo，而是围绕医院妇科超声的完整工作流：医生上传图像，系统结合检查方式和检查所见做多模态推理，再把逐图结果聚合成患者级诊断。

重点可以放在三个数字：训练规模是 10,587 例患者、196,255 张图像；当前推理使用 Fold 3 EMA 权重，患者级准确率记录为 0.8600；前端同时支持单例即时推理和 ZIP 批量推理。

右侧是界面质感的抽象：左边输入和结果，右边数据流和审计流，后面三页会分别展开方法、队列和治理闭环。

V2 多模态模型 图像主导门控融合 · EfficientNet-B3 + Medical BERT

Method

图像证据是主轴，文本在门控中补充上下文。

300×300 图像输入 EfficientNet-B3；检查方式与检查所见清洗拼接后送入医学 BERT。两路特征经 ImageDominantGatedFusion 生成三类 softmax。

图像特征
文本向量
融合特征
核心结论 不是“图像 + 文本平均融合”，而是让图像证据决定主方向，文本只补充临床上下文。
当前步骤
1. 图像证据先进入主干 DICOM / JPG / PNG 等图像统一转 RGB，Resize 到 300 x 300，保持与训练管线一致。
2. EfficientNet-B3 提取形态特征 最后特征维度为 1536，承担病灶形态、边界、回声模式等主要视觉证据。
3. 文本输入做临床上下文 检查方式与检查所见经过 clean_check_project / clean_check_seen 清洗后拼接；空文本走零向量。
4. 医学 BERT 输出 CLS 向量 阿里医学 BERT 产生 768 维文本向量，让“经阴道三维超声”等检查背景进入融合层。
5. gate 学习文本参与强度 两路特征先投影到 256 维，再学习 g 值：图像主导，文本只在有价值时补充。
6. 输出三类 softmax 概率 分类器给出正常、子宫内膜癌、息肉三类概率；患者级结果由逐图预测聚合得到。
融合逻辑 f = g · f_image + (1 - g) · f_text；分类器同时利用图像分支和融合分支。
1536 → 256图像投影
768 → 256文本投影
512 → 3分类输出
Text cleaning: clean_check_project / clean_check_seen / build_clinical_text

这一页讲方法。这里最重要的是“图像主导”四个字。模型不是把文本和图像平均混在一起，而是先分别投影，再由 gate 学习文本应该补充多少，最后保留图像分支和融合分支共同分类。

图像侧是 EfficientNet-B3，输入固定为 300×300，并使用 ImageNet 归一化。文本侧是阿里达摩院医学 BERT，输入是检查方式加检查所见，清洗逻辑和训练管线一致。无文本时系统走纯图像筛查，文本向量为 768 维零向量。

最终输出正常、子宫内膜癌、息肉三类概率，后续患者级结果不是单图结果，而是逐图结果再经过聚合策略产生。

这一页讲推理逻辑。后端的核心不是并发跑多个模型，而是把模型调用串行化。这样做是因为模型对象不适合多线程抢占，单执行器能避免稳定性问题。

系统用 heap 做优先级队列：单例任务优先级为 0，批量任务优先级为 5。所以医生在单例页面提交时，不会被一个大的批量 ZIP 长时间挡住。批量任务本身按患者串行推进，每个患者又按图像逐张进入队列。

单例流程是提交后立即返回 202 和 task_id，前端每秒轮询任务状态。每张图完成后保留图像级预测，所有子任务结束后触发 aggregation task，得到患者级结果。聚合策略有 mean、max_severity 和 majority_vote 三种。

FastAPI + SQLAlchemy + SQLite WAL · React + Tailwind + React Query

最后一页讲闭环。临床系统的价值不是模型单点准确率，而是模型结果能不能进入医生可解释、可追溯、可复核的工作流。

病例详情页把原图和 Grad-CAM 放在一起，医生可以切换每张图，同时右侧显示患者级概率和聚合策略。医生判断会作为 Judgment 保存，PDF 报告可以导出，历史记录也能按日期、类别和来源筛选。

数据库层面，SQLite 开启 WAL、busy_timeout 和 foreign_keys。核心表包括 cases、case_images、per_image_predictions、predictions、judgments、batch_jobs、sessions 和 audit_logs。审计日志用独立事务写入，即使业务回滚也不会吞掉审计轨迹，管理员页面可以筛选并导出 CSV。
