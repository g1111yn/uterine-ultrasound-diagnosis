# 子宫超声辅助诊断系统 PPT 源材料

## 1. 项目定位

子宫超声辅助诊断系统是面向医院妇科超声检查场景的 AI 辅助诊断工具。系统接收 JPEG、PNG、BMP、TIFF、DICOM 等格式的超声图像，通过深度学习模型输出三类预测概率：正常、子宫内膜癌、息肉。

系统面向临床使用流程，支持医生上传单个患者的 1 到 30 张图像，也支持通过 ZIP 批量提交数十到数百个患者。推理结果既提供患者级聚合诊断，也保留逐图预测与 Grad-CAM 热力图，帮助医生查看模型关注区域。

## 2. 临床与产品价值

- 多图像输入贴近真实超声检查，一个患者可包含多张切面图像。
- 图像与检查文字联合建模，保留医生检查方式和检查所见中的上下文信息。
- 单例任务优先于批量任务，避免医生现场操作被后台批量分析阻塞。
- 通过患者级聚合、逐图解释、PDF 报告、历史检索和审计日志形成完整闭环。
- 支持 DICOM 解码和窗宽窗位调整，兼容医院影像数据格式。

## 3. 当前 V2 模型架构

当前版本采用多模态融合模型：

- 图像编码器：EfficientNet-B3，输入 300 x 300，ImageNet 归一化，输出 1536 维图像特征。
- 文本编码器：阿里达摩院医学 BERT，使用 CLS 向量作为 768 维文本表征。
- 融合模块：ImageDominantGatedFusion，图像主导门控融合，256 维隐层。
- 分类器：512 → 256 → 3，输出 softmax 概率。
- 训练数据：10,587 例患者，196,255 张图像，5 折交叉验证。
- 推理权重：EMA 权重，Fold 3，患者级准确率 pat_acc = 0.8600。

文本输入由“检查方式 + 检查所见”拼接后送入医学 BERT。若医生未填写检查所见，系统进入纯图像筛查模式，文本向量为 768 维零向量。

类别顺序为：

1. 正常
2. 子宫内膜癌
3. 息肉

## 4. 推理管线

单次推理的主要步骤：

1. 图像加载：支持常见位图格式和 DICOM。
2. 图像预处理：转 RGB、Resize 到 300 x 300、ToTensor、ImageNet 归一化。
3. 文本预处理：clean_check_project、clean_check_seen 清洗，生成临床文本。
4. 编码：EfficientNet-B3 提取图像特征，医学 BERT 提取文本 CLS。
5. 融合：ImageDominantGatedFusion 按门控机制融合图文特征。
6. 分类：输出正常、内膜癌、息肉三类概率。
7. 解释：对 EfficientNet-B3 最后卷积层生成 Grad-CAM 热力图。
8. 聚合：多图结果通过 mean、max_severity、majority_vote 等策略聚合成患者级诊断。

## 5. 核心功能模块

### 单例推理

医生在单例推理页输入病例编号，选择检查方式，上传 1 到 30 张图像，可选填写检查所见。提交后系统返回 task_id，前端轮询任务状态。任务完成后展示患者级概率分布、最终分类、逐图预测与 Grad-CAM。

### 批量推理

批量任务通过 ZIP 上传，包含 manifest.csv 和按患者编号命名的子目录。系统异步执行，支持队列排队、批量历史、患者列表、颜色分类标签、逐图详情和分类汇总图。

### 病例管理

历史记录支持关键词搜索、日历日期选择、预测类别筛选、来源筛选。病例详情展示患者级诊断、多图预测、医生判断、原图、热力图和报告入口。

### 报告与解释

系统使用 reportlab 生成中文 PDF 诊断报告，并通过 Grad-CAM 辅助医生理解模型关注区域。报告和解释结果作为临床复核材料，而不是替代医生判断。

### 权限与审计

认证采用 bcrypt、HttpOnly + SameSite 会话 cookie，支持连续失败锁定和强制改密。审计日志记录登录、登出、创建病例、用户管理等操作，支持 CSV 导出。

## 6. 系统架构

后端采用 FastAPI 提供 API 服务，负责认证、任务提交、推理队列、病例管理、报告生成和静态文件服务。数据库使用 SQLAlchemy 2.x + SQLite，开启 WAL 模式以支持轻量并发。推理服务使用 PyTorch CPU 推理，并加载 EfficientNet-B3、医学 BERT、融合层和分类器权重。

前端采用 React 19、TypeScript、Vite、Tailwind CSS、React Router、React Query、Zustand 和 Axios。主要页面包括登录、单例推理、批量推理、历史记录、病例详情、批量详情、设置、用户管理、审计日志和统计看板。

任务流设计为异步模型：提交推理请求后立即返回 202 和 task_id，前端通过 /api/tasks/{task_id} 轮询状态。队列使用优先级机制，单例任务 priority = 0，批量任务 priority = 5，保证临床交互优先。

## 7. 后端 API 概览

- POST /api/predict：单例推理，表单包含 images、clinical_text、check_project、patient_no。
- POST /api/predict/batch：批量推理，上传 ZIP。
- GET /api/tasks/{task_id}：查询任务状态。
- GET /api/cases：病历列表。
- GET /api/cases/{case_id}：病历详情。
- POST /api/cases/{case_id}/judgment：提交医生判断。
- GET /api/cases/{case_id}/report.pdf：生成或下载 PDF 报告。
- GET /api/health：健康检查。
- GET /api/metrics：管理员查看推理延迟、队列长度等指标。

## 8. 运维与部署

系统支持 Linux systemd 部署和 Windows NSSM 服务管理。Linux 生产部署流程包括安装 Python 3.10、SQLite、rsync 等依赖，创建虚拟环境，安装 requirements，放置模型权重和 BERT 目录，初始化数据库和管理员，构建前端，启动 Uvicorn 服务。

硬件建议：

- 最低配置：4 核 CPU、8 GB 内存、50 GB SSD。
- 推荐配置：8 核以上 CPU、16 GB 内存、200 GB SSD。
- EfficientNet-B3 + BERT 首次加载约需 2 GB 内存，CPU 推理约 1.2 秒每图。

可选使用 Nginx 进行 HTTPS 反向代理。生产环境建议开启 COOKIE_SECURE、HSTS_ENABLED、FORCE_HTTPS_REDIRECT，并使用结构化 JSON 日志。

备份策略：通过 backup.sh 每天凌晨进行 SQLite 热备和 uploads 目录增量 rsync，保留 30 天。建议每月做一次恢复演练。

## 9. 故障排查要点

- model_loaded 为 false：检查 MODEL_CKPT_PATH 和 BERT_PATH 是否存在且可读。
- 推理异常：确认使用 EMA 权重、RGB 通道、BERT CLS 不做 L2 norm。
- 推理延迟升高：查看批量任务是否占用队列，检查 CPU 和内存状态。
- SQLite 锁：确认 WAL 和 busy_timeout，必要时重启服务释放长事务。
- 磁盘压力：优先备份并归档 uploads 目录，再清理旧数据。

## 10. 前端体验与设计方向

前端已有重构指南，倾向采用克制、温暖、低噪音的 Anthropic 风格设计系统。整体视觉关键词包括暖米白背景、深棕文本、低对比边框、12px 卡片圆角、8px 控件圆角、无阴影、少字重、语义色严格映射。

三类诊断语义色：

- 正常：绿色系。
- 子宫内膜癌：红色系。
- 息肉：黄色或警示色系。

关键界面需要支持医生快速扫描：输入区、上传区、队列状态、患者级概率、逐图卡片、热力图、医生判断、报告入口和历史筛选。

## 12. 风险边界与表达原则

PPT 中应明确该系统是辅助诊断工具，不替代医生最终判断。模型输出应被表述为“预测概率”“风险提示”“复核参考”，避免使用“确诊”“自动诊断替代医生”等绝对化措辞。需要强调医生判断、病理结果和临床流程仍是最终依据。
